Logarithmic Number System arithmetic simulator

Encode two numbers into LNS, run one operation entirely on the packed codes, and see every step: the sign/log encoding, the log-domain gap ΔL, which correction-term branch was taken, the correction value, the resulting code, and the decoded float.

Demo companion. This page is a dependency-free JavaScript port of lns_arith's formats.py, convert.py, logadd.py and ops.py, so it runs standalone from a file:// URL with no Python and no server. The full simulator — which imports the real package and adds the batch error experiment with charts — is webapp/app.py: run streamlit run webapp/app.py. The two agree bit for bit; a test in this repository checks that.

Format reference

  

  

    

      

        The log-add correction term for the selected format: the smooth line is the exact
        function, the stepped line is the quantised table a hardware implementation would
        hold. Addition needs this; multiplication needs nothing at all.
      

      

    

    

      

        Encoding. L = (code − bias) / 2^frac_bits is the base-2
        logarithm of the magnitude; the sign is a separate bit. Encoding rounds
        log2(|x|) × scale + bias to nearest and clamps — it never
        wraps.
      

      

        Zero. Code 0 is reserved as an exact-zero sentinel instead of being used as
        the most-negative magnitude slot. That costs one log-step of range at the bottom
        and buys an exact zero — a good trade for DNN tensors, which are full of
        zeros from ReLU, padding and masking.
      

      

        Overflow / underflow. Out-of-range magnitudes saturate at the extreme code
        and raise a flag. Underflow clamps to the smallest nonzero code rather than
        flushing to zero, because zero is reserved for exact zero.
